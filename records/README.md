# records/ · 开发记录

按天归档的**工作记录**：那天想解决什么、怎么决定的、为什么否掉另一条路、验证到什么程度、哪里还悬着。

## 和其他文档的分工

| 位置 | 回答什么问题 | 读者 |
|---|---|---|
| `CHANGELOG.md` | 这一版对外变了什么 | 使用者、升级的人 |
| `docs/spikes.md` | 这个 API/行为**实测**是什么样（契约与踩坑） | 接下来写代码的人 |
| `records/` | 那天**为什么**这么选，试过什么不行的 | 三个月后的自己 |
| `AGENTS.md` | 现在仓库里哪些不变式不能碰 | 任何接手的人 |

判据很简单：**能一句「改了什么」说完的进 CHANGELOG；能写成「X 实测返回 Y」的进 spikes；需要讲前因后果和取舍的进这里。**

## 约定

- 一天一个文件，文件名 `YYYY-MM-DD.md`，日期取**提交时间**，不取对话时间（跨零点时容易错）。
- 只写**有长期价值**的东西：被否掉的方案比选中的方案更值得记，因为它是将来重新考虑的边界。
- 不写「今天很顺利」「修复了一个 bug」这类结论，写**为什么错、错在哪一层**。
- 引用提交时用短哈希，便于 `git show` 回查。
- 记录里出现的数字（覆盖率、耗时、上限）应当来自真机验证，不是估算；没法验证就标「未验证」。
