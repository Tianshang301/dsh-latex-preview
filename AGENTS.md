# AGENTS.md

## Repo state (read this first)

- **The harness contract lives in `package.json`, and it is checked before any of this code runs** (2026-11-22): `engines.dsh` (`^0.2.2-rc.5`, i.e. `>=0.2.2-rc.5 <0.3.0`) is the author-side declaration the launcher reads; `dsh.manifestVersion: 1` names the manifest format; `dsh.bundle.patch` and `dsh.client` make the two halves loadable. `test/unit/manifest.test.ts` asserts the fields exist, that the range's version tuple matches what is actually installed, and that every `@deepseek-ai/*` package imported under `src/` is declared — an undeclared import crashes the host process at load time, where no unit test would see it. Bumping a dependency without bumping the range is a silent incompatibility, which is why both live in one commit.
- **A compile's input is a graph, not a file** (2026-11-22): `stable` is "the root text did not move **and** `sameBuildInput(pre, post)`", where the manifest is `services/build-input.ts`. Three things it must keep doing: (1) **TeX's own output is never an input** — `.aux/.toc/.bbl/...` are created by the run, so counting them makes every compile unstable and the convergence recompile never stops; (2) `missing`, `unreadable` and `truncated` all enter the digest and compare **symmetrically** — a chapter that appears is a change, an unreadable member that stays unreadable is not; (3) a scan that throws degrades to the root-only comparison, because failing closed means "no compile is ever stable". Convergence is bounded by `MAX_CONVERGE`; without it a formatter saving on every run keeps the panel on 正在编译. The credential deliberately does **not** carry the manifest digest: `sourceDigest` names the revision, the manifest is the *condition* of issuing — folding it in makes "compile, edit a chapter, accept the previous version" refuse and delete a valid pair.
- **An explicit `outDir` belongs to its root file, not the process** (2026-11-22): `request.outDir` is used, a configure for the **same** root keeps the current directory (that is what makes `configure({ review })` a settings refresh — `panel.tsx` never sends `outDir`), and any other root gets `dirname(root)/.latex-preview`. The root file is `resolve()`d before it becomes an identity, and a configure with **no** file hint applies to the workspace on screen instead of `process.cwd()`.
- **Four boundaries that new code must not quietly cross** (2026-11-18): (1) the `/pdf` mount takes a **getter** for its directory — the mount is registered before any workspace exists; (2) `CompileResult.artifactState` decides whether the panel may show a PDF at all, and `pdfPath === null` for `unavailable` (a path is not evidence); (3) the reviewer starts **after** `issueTrustFor`, because approving promotes the current PDF to the baseline; (4) a compile owns a `BuildContext` for its whole life — workspace, paths, `before`, `input`, the three revisions, the review mode and the credential it started with — and a `configure` may land at any point in it.
- **A workspace switch is a state machine, not a check** (2026-11-18): `configureOnce` is split into `prepareWorkspace` (resolve, read, restore — all of it confined to the candidate's own `outDir`) and `activateWorkspace` (one assignment block with no `await` in it). Nothing touches `this.workspace` until the candidate is ready, so a compile can never see a half-initialised workspace, and a configuration that fails leaves the running one alone. A repeat `configure` of the same workspace with the same source is a **settings refresh**: the PDF, both pairs and the revisions stay.
- **Artifact paths are leased, and the lease *waits*** (2026-11-18): the question is no longer "is this the active workspace's directory" but "are these paths spoken for by *any* task — current, queued or stale". Every queue task holds a `PathLease` on `resolve(paths.pdf)`, taken at **enqueue** (a task waiting in the queue is invisible to everything else, which is the hole), released in its `finally` (after the last I/O — never when the run is judged stale: staleness decides *publish*, not *write*). Each lease has an **identity** (`owner: symbol`, so `assertArtifactPathsQuiet` can exclude the caller's own claim — `commitActivation` holds its candidate's lease while it restores), a **mode** (writes exclude everything; `applyDiffDoc` is a *reader* of the live pair and is only blocked by writers — do not turn it into a writer or every diff build serialises behind every compile), and a **`running` flag** (queued reservation vs I/O in progress). Two different questions use the registry differently: `artifactPathsBusy` counts *any* lease on the key (the restore must not delete files a queued task will write), `assertArtifactPathsQuiet` counts only running peers (the queue guarantees queued ones run later). And the registry is backed by `services/path-lease.ts`, a **FIFO reader-writer lock that waits**: a writer meeting a two-minute diff build waits for it to drain instead of refusing (`artifact-busy` was the old behaviour — a project switch that *failed* because a reader was reading), and the reader waits for writers instead of reading bytes mid-flight. Waiting inside a queue task is safe because readers never enter the queue — no queue task waits on another queue task's lock, so there is no cycle. `restoreArtifacts` still refuses a running peer outright; it must never fire — it exists because this bug's recurring form is a new code path that forgets to look.
- **A colliding restore waits for the compile** (2026-11-18): `restoreArtifacts` *deletes* both pairs by name, so it must never run next to a compile that is publishing to the same names. `outputPathsClash` compares the candidate's PDF path with the active workspace's — the file name, not the directory, because two roots with different names in one `outDir` never touch each other. On a collision `prepareWorkspace` returns `restored: null` and `activateWorkspace` hands `commitActivation` to `enqueue`, so the switch is ordered against the compile instead of racing it. Do not widen this into "configure is queued": the non-colliding path is the common one, a first compile can take minutes, and the negative-control test exists to catch exactly that drift.
- **Publishing paths must not read `this`** (2026-11-18): the mechanical rule, because the bug recurs as "some helper quietly used a default parameter". Inside `compileOnce` and everything it calls — `issueTrustFor`, `publishCompileArtifacts`, `adoptBaseArtifacts`, `snapshotBaseFromCurrent`, `drop{Base,Recent}Artifacts` — do **not** read `this.workDir`, `this.state.rootFile`, `this.workspace.id`, `this.revisions()`, `this.acceptedSource`, `this.review` or `this.trusted`. They come from `ctx` (`WorkspaceContext` / `BuildContext`). Exceptions are the accessors whose whole job is reading the current state: `pathsOf`, `storesNow`, `currentContext`, `isCurrent`, `commit`. A grep over those functions should come back empty; `artifactPathsNow()` with its `= this.*` defaults was exactly this bug.
- **Every `await` is a boundary** (2026-11-18): after an async step, re-check `isCurrent(ctx)` before starting the next file or state operation, and write state only through `commit(ctx, …)` / `commitRevisions(ctx, …)`. The helpers encode it too and return `StoreOutcome` (`published` / `withdrawn` / `stale`) instead of `void`, because `null` used to mean all three at once. What a stale run must never do: start another store operation, or patch the state that replaced it. What it cannot undo: a file operation already in flight — which is why the paths come from the context, not from `this`.
- **Operations that move state share one queue** (2026-11-18): `enqueue()` serialises compiles, 接受, 撤销 and reviewer verdicts (`lifecycleQueue`); a queued task that needs a compile calls `compileOnce` **directly** — awaiting `runCompile()` from inside the queue waits on itself. **Both faces of a mutation go through the queue**: the `@Remote` method and `httpHost()`'s arrow are aliases for the same `acceptQueued` / `revertQueued`, not for the body. The route calling `applyAccept` directly is what let a click promote a baseline from a PDF a compile had written but not published. A mutation that loses its workspace commits nothing — no status line, no revision, no credential. `configure` deliberately stays on its own queue: a first compile can take minutes and switching projects must not wait for it, which is safe only because activation is atomic (and because a *colliding* restore joins the lifecycle queue; see below). The reviewer's model call stays outside the queue (25 s), and its verdict re-enters through `applyVerdict`, re-checked against workspace and revision.
- **Integrity is not provenance** (2026-11-18): a manifest proves the bytes are the ones it recorded; it never proves *which revision compiled them*. `services/provenance.ts` holds the credential — workspace id, source digest, both file hashes — and it is issued only right after a compile whose input was re-read and found unchanged. Every publish path (`publishCompileArtifacts`, `adoptBaseArtifacts`, `snapshotBaseFromCurrent`) requires it; absence means withdraw the view, never publish a guess. `BackupResult` (`complete`/`pdf-only`/`unavailable`/`failed`) is the compile's side of the same rule: the pair is copied to `.tmp` names, hashed, renamed only when both halves landed. `runCompile` is serialised on `lifecycleQueue` — the process was already single-flighted, the bookkeeping was not, and two interleaved bookkeepings published and then dropped each other's pair.
- **Restoring artefacts is part of the configuration snapshot** (2026-11-18): `restoreArtifacts(rootFile, outDir, source)` takes the workspace explicitly (on a first configure `state.rootFile` is still null) and returns state fields instead of patching them, because the commit that followed used to erase the result. A pair is restored only when its manifest still names the source on disk; a previous-compile pair is never restored — only the process that compiled it knows what it holds.
- **Three revisions, two diff paths, one manifest per pair** (2026-11-18): `services/revisions.ts` is the only place the semantics live — `accepted` (接受 / approving reviewer / every `open` compile), `previousCompile` (every successful compile whose content changed), `current` (what the PDF shows), with `advanceRevisions` / `acceptCurrent` / `diffBaseFor` / `parseDiffSide` all pure and unit-tested. `getDiffRegions({side})` has three values: `new` (accepted → current, on the live PDF), `base` (same comparison, drawn on the accepted pair) and `compile` (previous compile → current, drawn on the recent pair). Sides are parsed by `parseDiffSide` in **one** place: a stale two-branch copy in the HTTP route silently turned every `compile` request into `new`, and the response looked normal.
- **A pair is trusted only through its manifest** (2026-11-18): `services/artifacts.ts` publishes `main.prev.pdf` + `main.prev.synctex.gz` (accepted) and `main.recent.*` (previous compile) each with a `*.manifest.json` recording both sha256s and the source digest. Publish removes the manifest first, installs both files, writes the manifest last; `verify()` re-hashes both files and compares the revision id. Never trust "the files exist" — that was the earlier bug class (a failed rename left an older pair that looked paired). Compiles no longer promote: `compile.ts` leaves the pre-compile copies and the *service* decides which pair may claim them.
- **A half rollback is not a rollback** (2026-11-18): `rolledBack` is `pdfRestored && syncRestored`; when only one half lands, `rollbackIncomplete` is set and both pairs are dropped, because the page and its sync map may now describe different documents. A first compile that fails deletes its partial output instead of leaving a document that never compiled.
- **A change has two sides, and the diff knows both** (2026-11-18): `lineDiff` numbers `oldStart`/`oldLines` as well as the new lines, and `getDiffRegions({side})` returns regions for `new` (the live PDF) or `base` (the previous revision). On `base` a deletion is a **normal band** — `kind: 'removed'`, red with a midline strikethrough — because the text is still typeset there; on `new` it can only be a seam. `DiffRegion.seam` is the geometry flag that tells the viewer "no line of the shown document is under this" and replaces the old `kind === 'delete'` guess. The panel always fetches `new` (it drives the review count) plus whichever revision view is on screen, and pushes `{type:'mode', readOnly}` while an older document is up: selection, double-click and band clicks there would resolve against **old** line numbers. Verified on a real boot; see `docs/spikes.md` §B21/§B22/§B23.
- **Diff fragments must stay line-aligned** (2026-11-18): `diff_cleanupSemantic` has to run while one line is still one character (`diff_linesToChars_` → `diff_main` → `cleanupSemantic` → `diff_charsToLines_`). Run after `diff_charsToLines_` it shifts boundaries to character-level edges, every block's line count gains one and bands land on the line *after* the change. Also: `synctex view` answers a **blank** line with the *next* rendered line's box, so blank lines are filtered out of a resolved range (`typesetLines`) — otherwise a deleted paragraph paints the untouched line below it.
- **Deletion display is two-layer** (2026-11-16): `DiffRegion.text` carries the **removed** source lines (capped 8 lines × 200 chars — `textOf` in `diff-regions.ts` reads only delete blocks: the new lines render under the band, the removed ones are the invisible ones). The viewer draws a `−N 行` chip at the text column's right edge (`viewer/viewer.js` `paintDiffPage`) and pops the removed lines up struck-through on hover (`showDiffRows`; `hideDiffFlyout` retires both flyouts). The faithful rendering is `services/diffdoc.ts` — latexdiff merges both revisions into a third document compiled on demand via `POST diff-doc` (single-flight, `probeLatexdiff` cached) — but MiKTeX's `latexdiff.exe` needs system Perl, absent on this machine, so the probe degrades to an actionable message, never a throw. `viewer/index.html` imports `viewer.js?v=<page v>` because `/assets` serves `max-age=3600`. State invalidation: accept/revert/auto-verdict/new-content compile all patch `diffDocUrl: null`; the panel snaps back to live view when a **newer** version clears it (`diffDocAt` ref guards the click-to-poll race).

- **Previous-revision artefacts are paired** (2026-11-18): `compile.ts` backs up PDF **and** `.synctex.gz` before every run and restores both on failure (restoring only the PDF left a new sync map describing a document that is no longer on screen). On success the pair is promoted to `main.prev.pdf` + `main.prev.synctex.gz` — the basenames must match, because `synctex view -o <pdf>` looks up the map by name and silently finds the current one otherwise. Promotion to *baseline* is the service's call, not the compiler's: `adoptBaseArtifacts(before)` keeps the pair only when `previousSource === before`, and 接受 / auto-approval / revert call `snapshotBaseFromCurrent()`; anything else deletes it. `baseRevisionId` (sha1 of the baseline source) is what later code must check before mapping old line numbers. See `docs/spikes.md` §B20.
- **Overlay paint is guarded** (2026-11-18): `paintDiffPage` is async and `pagerendered` fires on every zoom/scroll, so a paint records `diffGeneration` and a per-page ticket in `pagePaintTokens`, and discards its own result if either moved, if `pdfDocument` was replaced, or if the page left the DOM. The new layer is appended **before** the old one is removed, and `painted` is replaced only after that commit. Bands carry no `mix-blend-mode` (multiply tinted them with whatever was underneath), the seam height is `clamp(2, 8, lineHeight × 0.55)`, and `viewer.css` is cache-busted with the page's `?v=` like `viewer.js`. Rotation is **not** handled: `getViewport()` applies `/Rotate` while SyncTeX boxes are unrotated. See `docs/spikes.md` §B19.
- **Diff overlay works** (2026-11-16): `getDiffRegions` turns source hunks into PDF bands via `synctex view`. The box top is `v - H`, **not** `y` (using `y` drops every band a line low); a deletion gets a red hatched band anchored at the foot of the line *above* the hole (see the first bullet for the removed-text chip), because `synctex view` answers for `\end{document}` with the page-number box. Bands are `pointer-events: none` and positioned in percent, so zoom and the text layer's gestures are untouched. The diff baseline is `previousSource` vs `compiledSource` — both snapshots of *compiled* content, advanced only when the content really changed. See `docs/spikes.md` §B17.
- **Review gate works** (2026-11-16): `review` has three values — `manual` (reference stays until 接受), `auto` (a **separate one-shot model call** reviews; reject rolls the source back), `open` (no gate). The reviewer is not the session's Agent: that Agent wrote the change. Its route comes from `agent.session.requestHeader().config`, falling back to `ctx.agentDefaultModel.currentSelection()` because a fresh Session has no header; an unreadable or timed-out verdict degrades to manual, never to approval. `applyRevert()` writes the root file — the only destructive action — so the button arms twice. See `docs/spikes.md` §B18.

## What is being built

`dsh-latex-preview`: a DSH (DeepSeek Harness) **Cordis dual-half plugin** (Host = Node, Client = web) for live LaTeX preview. Stack: Tectonic compiler, PDF.js viewer, SyncTeX jumps, `diff-match-patch` line diff, CodeMirror 6. TypeScript throughout.

## Non-obvious invariants (easy to get wrong)

- Host services extend Cordis `Service` and call `super(ctx, 'latexPreview')`; the service is exposed as `ctx.latexPreview`.
- Host acquires other services with `ctx.inject(deps, cb)`, **not** `ctx.get()` inside `apply` (services may not exist yet).
- Client declares hard deps via `export const inject = ['latexPreview']`; optional deps use `ctx.get` and probe at use site.
- Register client slots as `ctx.slots.inject(key, () => ctx.slots.register(...))` and **never wrap it in `ctx.effect`** — doing so throws `Invalid effect` and the panel silently never appears.
- Every route/timer/listener needs a disposer registered with `ctx.effect(() => dispose, label)`.
- `package.json` is ESM (`"type": "module"`) for Host, but built `lib/client.js` must be a **lazily-loaded CJS bundle**: only top-level statement is the module-loader call, side effects inside the factory.
- Do **not** use `tectonic -X watch` (known broken combo). Use chokidar + debounce.
- Compile safety: copy PDF to `.pdf.prev` before compiling; on failure restore it. A failed compile must never blank the PDF.
- `draftMode` = rewrite source after `\documentclass` with `\PassOptionsToPackage{draft}{...}`; it is not a Tectonic CLI flag.
- SyncTeX: always shell out to the `synctex` CLI. Hand-parsing `.synctex` is explicitly forbidden by the spec/manpage.
- PDF.js CSS coords vs synctex PDF coords differ: flip y, scale `72/96`, account for page scale/padding/scroll offset.
- Scroll preservation: `captureScrollState()` must run **before** loading the new PDF; clamp restored page with `Math.min` (out-of-range pages are silently ignored).
- `tectonic` and `synctex` are user-provided binaries; verify both at startup. Official binaries: win-x64 / macos-universal / linux-x64; arm64 needs `cargo install tectonic`.

## Privacy boundary (product requirement)

Compile, render, SyncTeX, and diff run on the local machine. Only error context / annotation anchors are sent to the DSH Agent, via `createUserMessage({ content, source })` + `agent.steer()`. A redaction switch (default off) must be able to send only message + line number. Warn on first enable and on every send.
